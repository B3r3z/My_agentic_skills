# ASD-STE100 Issue 9 rule index

Use this index to locate the relevant passage in the [official standard](https://www.asd-ste100.org/). The topics below summarize the sections. Check the wording and exceptions in the requested edition before reporting a numbered violation.

| Start here | What to inspect |
| --- | --- |
| Words (1.1–1.14) | Look up approved usage and forms. For a domain term, check technical nouns (1.5) or technical verbs (1.12). Check consistent naming under 1.11. |
| Multi-word nouns (2.1–2.2) | Can the reader tell how the nouns relate? Would a preposition or a defined short form help? |
| Verbs (3.1–3.7) | Check the verb form and voice. Consider whether a verb can replace a noun phrase (3.7). |
| Sentences (4.1–4.5) | Check complete grammar, articles, links between sentences, and lists of complex items. |
| Procedures (5.1–5.5) | Check the 20-word limit (5.1), the number of instructions (5.2), the imperative (5.3), where the condition appears (5.4), and the content of notes (5.5). |
| Descriptions (6.1–6.6) | Check the order of new facts, the 25-word sentence limit (6.3), and the six-sentence paragraph limit (6.6). |
| Safety instructions (7.1–7.3) | Check the hazard label, the opening command or condition, and the statement of consequences. |
| Punctuation and word count (8.1–8.7) | Apply the edition's counting rules for identifiers, quoted text, and lists before reporting a length violation. |
| Writing practices (9.1–9.4) | Check word meanings, consistency, and whether a sentence needs restructuring to keep its meaning. |

For example, in “Run `import --retry` if the first import fails,” the condition comes after the command. Suggest “If the first import fails, run `import --retry`.” In a Plain review, that explanation is enough. For a numbered finding, look up the procedural rule and cite its verified number.
